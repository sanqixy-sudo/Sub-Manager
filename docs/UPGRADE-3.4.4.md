# V3.4.4 稳定性升级

本版数据库为 V11，保留端口 7777、/data、现有组 Token 与公开地址。
本地代码修改不代表服务器已经更新。部署前需先完成镜像 CI 和真实客户端验收。

## 升级前

- 记录当前容器的镜像 ID、启动参数、环境变量和 /data 挂载。不要把 inspect 输出或备份上传 GitHub。
- 使用提交号标记镜像；构建传入 `--build-arg BUILD_REVISION=<提交号>` 与 `--build-arg BUILD_TIME=<UTC时间>`。
- 保留旧镜像，先构建新镜像成功再停旧容器；不要直接覆盖旧源码目录或提前删除旧容器。
- 停止旧容器后，使用新镜像的 `python -m app.backup /data /backup/<独立时间戳目录>` 做完整离线备份。
  将原数据只读挂载到 /data，将独立备份目录挂载到 /backup，并用 `--entrypoint python` 覆盖入口。
  备份包含 SQLite 一致性副本及加密密钥、缓存等完整数据；已有目标目录会拒绝覆盖。
- 后台自动迁移的数据库备份不能代替完整 /data 备份；缺失 manual-node.key 将无法恢复手动节点。

## 切换与验证

1. 将已停止的旧容器重命名保存，使用原挂载和运行参数启动新镜像，仍映射 7777。
2. 检查 `/api/ready` 返回 200。`/api/health` 用于诊断，不再把仅数据库正常当成所有依赖可用。
3. 在设置页核对版本、构建提交；检查 SQLite `PRAGMA user_version` 为 11。
4. 验证原公开地址、纯手动组、一个远程组、别名/分类/排序及一个真实节点的双目标测活。
5. 确认 scheduler 轮询与下次测活时间、通知测试发送和历史记录。
6. 任一核心检查失败，不删除旧容器或备份；按下节回滚。

## 回滚

停止新容器。先将升级后的 /data 保留到独立故障快照，再恢复升级前的完整 /data 备份。
恢复原容器名称和旧镜像，使用原参数启动，并核对旧公开 URL。
**不能只换旧镜像，让旧版本继续写 V11 数据库。** 回滚会放弃备份之后新增的配置和记录。

## 兼容说明

- 白名单只相信 Uvicorn 已验证的客户端 IP。反代须明确配置 `FORWARDED_ALLOW_IPS` 为代理 IP/网段，禁止使用 `*`。
  边缘反代应重建 X-Forwarded-For，不直接相信外部传入的首地址；同时避免绕过边缘代理直接访问容器端口。
- 仍只有旧小时键的数据库会转换成分钟；已有分钟配置保留。
  如果此前旧版本已经错误写入 30 分钟，无法判断是用户主动设置还是旧缺陷造成，本版不会擅自改回；请核对设置。
- 启动时先读取旧 last-good 缓存建立不透明身份映射。若升级前缓存与身份信息均缺失，无法可靠恢复跨格式节点关联。
- 手动节点 URI 不回显；组表单与手动导入同事务提交。保存配置与下游生成是两个明确状态，失败仍保留 last-good。
- 节点测活只影响诊断，不自动停用或移除节点。历史最多 30 天 / 全局 50,000 条，达到总量上限会提前清理。
- 已保存 Webhook 不回显：留空保留、输入替换，清除需勾选明确选项。发送失败最多重试五次，送达状态可见。
- 旧 Token 的不可用配置仅在客户端更新并接受后生效，不能吊销已下载节点的连接凭据；泄露节点凭据需在节点服务器轮换。

## 交互决策依据

- 批量操作明确选中范围，加入分类不清除其他分类（product-design: `rule/name-object-scope-consequence`）。
- 保留上下移动按钮，拖拽不是唯一方式（`rule/gesture-has-control-alternative`）。
- 区分配置保存、下游生成、过期结果及失败重试，失败保留输入/历史（`rule/cover-reachable-states`、`rule/preserve-user-input`）。
- 不增加侧栏入口，复用节点页和已有分类页（`rule/smallest-intervention`）。

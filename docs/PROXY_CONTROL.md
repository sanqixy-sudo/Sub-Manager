# 代理服务管理（V3.5.0）

原有订阅组、公开 /s 地址和缓存不变。新增「代理服务」管理页（/#/proxy）和普通用户中心（/#/portal）。主控仍使用单容器、7777 和 /data；节点服务器各自运行 Agent 与托管 sing-box 内核。

## 首次部署

1. 停止旧主控后备份完整 /data，包括 secrets。构建新镜像并沿用原持久化目录启动。V12 数据库升级前自动备份，但数据库备份不能替代加密密钥备份。
2. 配置 HTTPS 反向代理，在系统设置填写 HTTPS 公开访问地址。该地址必须能被节点服务器访问，TLS 证书需受系统信任。
3. 打开「代理服务 → 服务器」，添加服务器名称和 IP/域名，生成安装命令，在对应服务器使用 root 执行。
4. 安装器支持 Debian/Ubuntu + systemd，以及 amd64/arm64。安装目录为 /opt/sub-manager-agent，配置为 /etc/sub-manager-agent/config.json，持久化累计计数为 /var/lib/sub-manager-agent/counters.json。不要复制同一份配置到多台机器。
5. 等待服务器在线。添加节点，选择 AnyTLS、VLESS + TLS 或 Trojan，填写监听端口及 TLS 名称。19091 保留给仅本机可访问的统计接口。
6. 在云安全组与服务器防火墙放通节点的 TCP 端口。安装器不会修改既有代理服务、Nginx 或防火墙，也不接管已有占用端口。
7. 创建套餐模板并选择节点，再创建用户、绑定套餐。没有用户授权或链路依赖的节点不会开启监听。
8. 复制该用户的 Mihomo / sing-box 订阅地址；也可让用户在 /#/portal 登录查看自己的套餐、节点和流量。

安装链接 15 分钟有效，配对成功后不可重放。重新生成命令不会立刻停用原 Agent；新 Agent 配对成功后，原运行凭据失效。同一目录只能对应同一主控与同一服务器记录。安装失败且令牌已使用时，重新生成命令后重试。

## AnyTLS 与证书

节点默认生成有效期一年的证书，秘密使用 /data/secrets/control.key 加密。Mihomo 输出使用证书 SHA256 指纹，sing-box 输出信任指定证书，均不关闭 TLS 校验。可以同时上传 PEM 证书及匹配私钥，证书的 SAN 必须覆盖填写的 TLS 名称。编辑留空保留现有证书。

本版没有 ACME 自动续期；证书过期前请上传新证书，并让客户端刷新订阅。证书过期的节点及依赖其的链式入口会停止。只提供原生 Mihomo 和 sing-box 个人输出，不把不支持的 AnyTLS 配置强塞给旧转换器。

## 链式线路

编辑入口节点的「下一跳」为另一个托管节点，例如香港入口 → 日本落地 → 目标网站。落地节点也可以设置下一跳，最多 8 跳。系统拒绝环路。

主控为每条物理落地节点保存独立内部中转凭据。中转账户不分配给最终用户，不计入用户套餐；用户在其实际接入的入口按个人凭据计费。下一跳停用、服务器停用或证书过期时，依赖它的入口配置同步撤销，不会静默改为直连。

本轮链路是代理协议的服务端出站串联，不包含纯端口 DNAT、画布编排、分支选路、负载均衡或用户自助指定出口。

## 用户、套餐与流量

- 用户门户与管理员后台使用不同会话。普通用户不能调用管理 API 或查询别人的套餐。
- 每次绑定套餐产生独立实例及节点凭据，同一用户可绑定多个套餐，也可重复绑定同一模板。
- 模板管理节点范围、流量额度、重置周期和新实例默认有效期。空节点范围表示零节点；模板修改同步已绑定实例的授权范围和额度，修改默认有效期不改现有实例的到期日期。
- 每个实例单独计算到期及流量。节点入口倍率影响之后采集的增量，历史账本不重算。GB 按 1024³ byte 计，当前计费为上传 + 下载再乘入口节点倍率。
- 用户停用、套餐或实例停用、到期、额度用尽，均会在服务器下次同步时撤销相关用户凭据。重新启用、续期、周期重置后恢复原凭据。
- 「重置订阅地址」只更换订阅下载令牌，不更换代理密码；需要禁止已下载节点继续连接时，请停用用户/实例。
- 正常采集及同步周期为 10 秒；超额执行有采集延迟，不能宣称零超用。服务器失联时最多保留 120 秒配置租约，到期由 Agent 本地看门狗停止托管内核。没有控制面高可用时，应明确这一可用性取舍。
- Agent 使用累计高水位上报，主控事务去重处理重放和乱序，重启/重新配对时需保留本机 counters.json。主机永久故障会丢失最后一次持久化之前的少量流量。
- 周期跨界时，首次采集先入旧周期再推进基线；边界附近最多一个采集间隔的流量可能归入前一周期。每日账本按 UTC 日保存。
- 本版尚不提供带宽限速、设备数限制、订单支付或 Telegram Bot。

## 内核构建与本地开发

官方 sing-box 预编译包不含本项目使用的 V2Ray StatsService。Dockerfile 使用 Go 1.27.3 构建固定 sing-box v1.14.4，启用 with_v2ray_api、with_utls，并同时准备 Linux amd64/arm64 内核。服务器从主控下载内核并校验 SHA256，首次安装不需要在节点机上编译。

本地开发需自行准备 Go 1.27.3：

```text
python scripts/build_proxy_core.py
```

默认输出 agent/bin/sing-box-linux-amd64 和 sing-box-linux-arm64。未构建内核时相关下载接口返回 503。国内环境如需 Go 模块代理，可设置可信 GOPROXY，但不要关闭校验数据库。

运行回归：

```text
python -m pytest -q
```

真实内核集成测试需要设置 SING_BOX_BINARY 指向启用统计功能的内核；测试使用回环地址、临时证书及临时数据库，不连接生产节点。Windows 可使用构建参数 --platforms windows/amd64。

## 运维与恢复

```text
systemctl status sub-manager-agent
journalctl -u sub-manager-agent -n 100
systemctl restart sub-manager-agent
```

配置更新会重启该服务器的托管内核，正在使用的连接可能中断。校验失败保留原配置，启动/端口绑定失败尝试恢复原配置；面板只有收到 Agent 实际应用版本后才显示已同步。

升级回滚时，停止新主控并保存当前 /data 故障快照，再恢复升级前完整 /data 和旧镜像。V3.4.4 不能写入 V12 数据库。卸载 Agent 时先停用该服务器，确认租约过期停止代理后，再停止并禁用 sub-manager-agent.service；保留 counters.json 供对账。

第三方内核：sing-box v1.14.4，源码 https://github.com/SagerNet/sing-box/tree/v1.14.4 ，许可证 GPL-3.0-or-later。构建脚本不修改上游源码，仅启用构建标签并设置版本字符串。

构建同时保留上游许可证及对应源码归档，可通过 /api/agent/upstream/sing-box-LICENSE 和 /api/agent/upstream/sing-box-source.zip 获取。

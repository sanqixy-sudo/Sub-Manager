# 验收标准 / 测试场景

Codex 完成开发后至少跑通以下场景。

## A. 部署

- `docker build -t sub-manager:latest .` 成功；
- 单容器运行；
- 对外只需 7777；
- `GET /api/health` 能看到 app 与 converter 状态；
- 删除并重建容器但保留 `/data` 后，所有订阅组/设置/Token 仍在。

## B. 首次登录与 Web 设置

- 默认 `admin/admin` 可登录；
- 页面明显提示修改默认密码；
- Web 修改系统名称；
- Web 设置 `https://sub.example.com`；
- Web 修改用户名和密码；
- 改密码后旧 session/token 失效；
- 新复制的订阅 URL 立即使用新域名，无需重启。

## C. 多订阅组

创建：

```text
组 A：4 个上游 + Mihomo + Surge
组 B：2 个上游 + Mihomo
组 C：3 个上游 + QuanX + Loon
```

要求：

- 三组完全独立；
- 每组 Token 不同；
- 修改组 B 不影响 A/C；
- 重置组 B Token 后，B 的旧 URL 404，A/C 不受影响。

## D. 输入兼容

至少准备以下 fixture：

1. 原始 base64 节点订阅；
2. 纯 URI 文本；
3. 完整 Mihomo YAML；
4. 3x-ui `/clash/` 风格完整 YAML；
5. 单节点；
6. 带“剩余流量/套餐到期”等伪节点；
7. HTTP 500 上游；
8. 超时上游；
9. 返回 HTML 登录页的错误上游。

把 1~6 混合放入同一组，能够正确合并；7~9 不应默认拖死整个组。

## E. Clash/Mihomo 输出

导入 Clash Verge 后：

```text
PROXY
├── ♻️ 自动选择
├── DIRECT
├── 节点 A
├── 节点 B
└── ...
```

必须：

- 能手动点节点 A/B；
- 自动选择正常测速；
- 伪节点不出现在 selector；
- `规则 / 全局 / 直连` 客户端模式可正常使用；
- 规则模式下大陆直连，其他走 PROXY。

## F. 多输出效率

一个组 5 个上游 + 5 个输出刷新时：

- 上游总请求次数约等于 5，而不是 25；
- 上游拉取一次后复用标准化结果生成全部输出；
- 输出可并行渲染。

## G. 容错

- 一条上游失败，其他成功：组状态 `partial`，仍生成订阅；
- 一条上游失败且有它自己的旧快照：可按设置使用旧快照；
- 所有上游失败但输出有 last-good：公共 URL 仍返回 last-good；
- 所有上游失败且无缓存：公共 URL 返回明确 502；
- 错误页面/日志不出现完整上游 URL/token。

## H. 定时刷新

- 组 A 设 10 分钟，B 设 30 分钟；
- scheduler 按各组周期执行；
- 公共请求遇到过期缓存可触发刷新；
- 并发请求同一组只执行一个 refresh job。

## I. UI

- 桌面 1366/1920 宽度无横向爆版；
- 手机宽度可用；
- 长 URL 不撑破卡片；
- 错误信息折叠且脱敏；
- 批量粘贴 20 条上游可正常解析；
- 上游诊断能逐条显示状态、耗时、bytes、最后成功；
- 订阅地址弹窗可一键复制。

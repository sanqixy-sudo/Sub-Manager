# 产品开发需求（最终版）

## 1. 产品定位

把 CareyWang/sub-web 这种“临时订阅转换器”改造成一个**自托管、可持久化、可自动同步的私人订阅管理系统**。

核心体验：用户只在客户端保存自己域名下的固定订阅地址；真实上游订阅 URL 由服务器保存和自动更新。以后机场节点变化、增加/删除节点，客户端刷新固定 URL 即可拿到最新内容。

产品不是面向多人售卖订阅，而是偏私人/小团队运维工具。

---

## 2. 核心数据模型：订阅组

必须以“订阅组”为一级对象，而不是单个 URL。

示例：

```text
主力节点组
├── 上游订阅 A
├── 上游订阅 B
├── 上游订阅 C
├── Mihomo 输出
├── Surge 输出
└── QuanX 输出

美国家宽组
├── 上游订阅 D
├── 上游订阅 E
└── Mihomo 输出

备用组
├── 上游订阅 F
├── 上游订阅 G
├── 上游订阅 H
└── Clash 输出
```

要求：

- 订阅组数量不做低限制；
- 每组可以添加多个上游 URL；
- 上游可以单条添加，也可以批量粘贴；
- 支持 `名称 | URL` 批量格式；
- 每条上游可独立启用/停用、命名、排序、删除；
- 每组拥有独立 Token；
- 每组拥有独立自动拉取间隔；
- 每组拥有独立 last-good 缓存；
- 每组拥有多个输出客户端；
- 一个组修改/删除/重置 Token 不影响其他组。

---

## 3. 上游订阅兼容性

这是最高优先级功能之一。

系统必须兼容：

- VLESS / VMess / Trojan / SS / SSR / Hysteria2 / TUIC / AnyTLS 等常见原始订阅形式；
- base64 编码的节点 URI 列表；
- 完整 Clash/Mihomo YAML；
- 3x-ui `/clash/...` 返回的完整 Clash 配置；
- 单节点订阅；
- 同组多个链接混合不同格式。

不能假设所有输入都是 subconverter 最理想的原始 URI 订阅。

### 上游拉取

每次组刷新：

1. 对该组所有启用上游并发拉取；
2. 每条记录 HTTP 状态、响应类型、字节数、耗时、最后成功时间；
3. 正常结果保存本地快照；
4. 单条失败时，如果有该上游 last-good 快照，可按设置使用；
5. 默认“跳过单条失败上游”；
6. 如果至少一个上游有效，继续生成输出，状态记为 `partial`；
7. 如果全部失败，优先返回该组历史输出 last-good 缓存。

**多输出生成时，上游只能拉取一次。** 获取到统一标准化节点集合/快照后，再并行渲染多个输出。

---

## 4. 输出客户端

每个订阅组可以通过 `+ 添加客户端` 手动添加多个输出。

至少支持：

- Mihomo / Clash Meta
- Clash
- ClashR（如底层仍支持）
- Surge 2
- Surge 3
- Surge 4/5
- Quantumult
- Quantumult X
- Loon
- Surfboard
- V2Ray / Shadowrocket 节点列表
- SS
- SSR

每个输出独立配置：

- 客户端类型；
- 输出显示名称；
- URL slug；
- 客户端建议更新间隔；
- 启用/停用。

公开 URL 形式：

```text
https://sub.example.com/s/{group_token}/{slug}
```

真实上游 URL 永远不出现在公共地址中。

## 5. Clash / Mihomo 代理组行为

用户明确要求能够**手动选择具体节点**，不能只保留自动选择。

目标结构：

```text
PROXY
├── ♻️ 自动选择
├── DIRECT
├── 真实节点 01
├── 真实节点 02
├── 真实节点 03
└── ...全部真实节点

♻️ 自动选择
├── 真实节点 01
├── 真实节点 02
├── 真实节点 03
└── ...全部真实节点
```

不要生成：

- 香港组 / 日本组 / 美国组；
- Netflix / Telegram / AI / Disney 等业务组；
- 落地机组；
- 用户之前复杂 Surge 配置里的层层嵌套组。

用户在 Clash Verge 里自己手动点任意具体节点，或者选择自动测速。

- `references/clash-verge-proxy-selection.png`
- `references/clash-verge-subscriptions.png`

## 6. 默认规则

只需要一套简单常用规则：**大陆直连，其他代理**。

逻辑：

```text
局域网 / 私有地址 -> DIRECT
中国大陆域名      -> DIRECT
中国大陆 IP       -> DIRECT
GEOIP CN          -> DIRECT
其他              -> PROXY
```

对于 Mihomo/Clash 可优先使用稳定的 geosite/geoip 或 rule-provider 方案；对 Surge/QuanX/Loon 则渲染成各客户端能正确理解的等价规则。

注意：规则逻辑一致即可，不要求不同客户端生成的文本完全一样。

客户端自身仍可以切换：

```text
规则 | 全局 | 直连
```

这是客户端运行模式，不是后台的规则模板选择。

---

## 7. 伪节点过滤

机场经常把以下信息伪装成节点：

- 剩余流量
- 套餐到期
- 距离下次重置
- 建议每天更新
- 官网更新提示
- “如果很少节点可用...”

这些默认不能进入 `PROXY` 和 `♻️ 自动选择`。

过滤正则必须可以在 Web 系统设置中编辑。

不向下游发送 HTTP `Subscription-Userinfo`。多上游额度不同，透传任意一个上游都会造成误导；节点名称内明确存在的独立流量/重置信息仍可参与智能改名。

---

## 8. 自动更新与缓存

每个订阅组可以设置：

- 5 分钟
- 10 分钟
- 30 分钟
- 1 小时
- 3 小时
- 6 小时
- 12 小时
- 24 小时
- 自定义分钟数

刷新触发有两种：

1. 后台 scheduler 定时刷新；
2. 客户端请求时发现缓存过期，触发一次按组刷新。

必须做同组刷新锁，避免多个客户端同时请求造成重复刷新。

### Last-good

- 每个输出保存最后成功配置；
- 上游/转换失败时默认继续返回最后成功配置；
- 后台清晰提示当前返回的是旧缓存；
- 用户可在 Web 设置关闭该行为。

---

## 9. 上游诊断与可观测性

每条上游应该能看到：

- 正常 / 异常 / 使用旧快照；
- HTTP Status；
- Content-Type；
- 响应大小；
- 拉取耗时；
- 最近成功；
- 最近错误（脱敏）；
- 是否从缓存读取。

订阅组卡片应看到：

- 上游总数 / 正常数；
- 输出数；
- 上次刷新状态：正常 / 部分成功 / 失败；
- 上次成功时间；
- 下次计划刷新；
- 刷新耗时；
- 可选：标准化后节点数量。

提供：

- 立即更新；
- 诊断上游；
- 查看订阅地址；
- 编辑；
- 复制组；
- 删除；
- 重置公开 Token。

## 10. Web 系统设置

用户要求“很多设置 Web 化”。至少包括：

### 基础

- 系统名称；
- 公开访问地址/域名，例如 `https://sub.example.com`；
- 当前实际监听端口显示：7777。

### 管理员

- 管理员用户名；
- 管理员密码；
- 默认首次安装：`admin / admin`；
- 首次登录明显提示修改默认密码。

### 默认值

- 新建订阅组默认拉取间隔；
- 新建输出默认客户端；
- 默认客户端建议更新间隔。

### 刷新/容错

- 后台 scheduler 开关；
- 单上游失败是否跳过；
- 是否使用 last-good；
- 上游 User-Agent；
- 上游超时；
- 转换超时；
- 伪节点过滤正则。

域名修改后，新复制的订阅地址立即使用新域名，不要求重启容器。

---

## 11. UI / UX 重做要求

当前原型 UI 被用户明确评价为“很粗糙”。需要重做，而不是小修。

要求：

- 现代、干净、专业的管理后台；
- 桌面端优先，同时手机可用；
- 订阅组列表信息密度高但不拥挤；
- 重要状态用清晰 badge；
- URL/错误文本不能撑爆布局；
- 错误详情用折叠/弹窗，且始终脱敏；
- 编辑订阅组时，上游和输出客户端应是结构化卡片/表格，而非大量裸输入框堆叠；
- 支持批量粘贴上游；
- 操作成功/失败有 toast；
- 危险操作二次确认；
- 默认账号警告明显；
- 公开订阅 URL 一键复制。

建议把目前 `app/static/index.html` 这种单文件 CSS + HTML + JS 拆成真正的前端工程（Vue 3 + Vite / React 均可），构建后仍可放在单容器中由 FastAPI/Nginx 提供静态文件。

---

## 12. 安全要求

必须满足：

- 上游订阅 URL 在数据库中可存，但 API 默认不应把完整 URL无条件回显到普通列表；编辑页需要时才返回；
- 错误日志不得包含完整 URL、token、UUID、password；
- 管理员密码只存安全哈希；
- 默认 `admin/admin` 仅用于首次登录，并有强提醒；
- 公共订阅路由不需要后台登录，但必须依赖高熵 Token；
- Token 可一键旋转，旧 URL 立即失效；
- 反代后正确识别 `X-Forwarded-*`；
- 不要把 subconverter 的 25500 暴露公网；
- 生产环境仅对外暴露 7777（或仅绑定 127.0.0.1 再反代）。

## 13. Docker / 部署硬约束

必须是**单容器 Docker**。

统一端口：

```text
7777
```

数据：

```text
/data
```

示例：

```bash
docker run -d \
  --name sub-manager \
  --restart unless-stopped \
  -p 127.0.0.1:7777:7777 \
  -e TZ='Asia/Shanghai' \
  -v /opt/sub-manager/data:/data \
  sub-manager:latest
```

1Panel/Nginx 反代：

```text
https://sub.example.com -> http://127.0.0.1:7777
```

重建容器不能丢数据。
